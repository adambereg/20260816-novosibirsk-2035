# Content Contract v0.1.1

Этот документ определяет стабильный интерфейс между Markdown-контентом, текущим Node.js builder и будущим Publisher.

## Размещение и slug

Каждая статья — отдельный файл:

```text
content/articles/<slug>.md
```

Имя файла и front matter поле `slug` вместе определяют URL:

```text
content/articles/gorod-na-korotkih-rasstoyaniyah.md
→ /articles/gorod-na-korotkih-rasstoyaniyah/
```

`slug` должен содержать только строчные латинские буквы, цифры и одиночные дефисы. Имя файла без `.md` обязано точно совпадать с front matter полем `slug`; несовпадение и повторяющийся slug считаются ошибками сборки.

## Обязательный front matter

```yaml
---
title: "Город коротких расстояний"
slug: "gorod-na-korotkih-rasstoyaniyah"
description: "Короткое описание материала для карточек и поисковых систем."
publishedAt: "2026-08-16"
category: "Городская среда"
featured: true
draft: false
cover: "/images/articles/gorod-na-korotkih-rasstoyaniyah/cover.webp"
coverAlt: "Пешеходная улица в зимнем Новосибирске"
---
```

Семь базовых полей обязательны:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `title` | string, 1–120 символов | Заголовок страницы и карточки |
| `slug` | string | URL-идентификатор; точно совпадает с именем файла |
| `description` | string, 1–240 символов | Анонс и SEO description |
| `publishedAt` | string `YYYY-MM-DD` | Дата публикации; значение рекомендуется заключать в кавычки |
| `category` | string, 1–60 символов | Редакционная рубрика |
| `featured` | boolean | Разрешает статье стать главным материалом на главной |
| `draft` | boolean | Полностью исключает статью из production build |

Два поля обложки optional и указываются только вместе с файлом изображения:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `cover` | string | Абсолютный путь сайта к обложке внутри `/images/articles/<slug>/` |
| `coverAlt` | string, 1–240 символов | Содержательное текстовое описание обложки; обязательно, если указан `cover` |

`cover` и `coverAlt` можно полностью удалить, если у статьи нет обложки. В этом случае текстовый layout сохраняется без placeholder. Неизвестные поля считаются ошибкой. Это защищает pipeline от опечаток и делает контракт предсказуемым.

## Markdown body

После front matter должен находиться непустой Markdown. Поддерживается GitHub Flavored Markdown: абзацы, заголовки `##`–`######`, ссылки, списки, цитаты, emphasis, code и таблицы.

Ограничения:

- заголовок первого уровня `#` не используется: единственный `<h1>` строится из `title`;
- сырой HTML запрещён;
- ссылки допускают `http:`, `https:`, `mailto:`, абсолютные пути сайта, относительные пути и `#fragment`;
- `javascript:` и другие небезопасные протоколы запрещены;
- тело статьи не должно дублировать front matter.

## Изображения

Markdown-файл и каталог его изображений образуют единый publication package:

```text
content/articles/<slug>.md
+
public/images/articles/<slug>/*
```

Изображения статьи хранятся только в `public/images/articles/<slug>/` и вставляются в Markdown абсолютным путём сайта:

```markdown
![Содержательное описание](/images/articles/gorod-na-korotkih-rasstoyaniyah/street.jpg)
```

Внешние URL и относительные пути для изображений не допускаются. Для каждого Markdown-изображения обязателен непустой `alt`.

Обложка задаётся optional front matter парой:

```yaml
cover: "/images/articles/<slug>/cover.webp"
coverAlt: "Содержательное описание изображения"
```

Если указан `cover`, поле `coverAlt` обязательно. Путь `cover` должен находиться строго внутри `/images/articles/<slug>/`, а соответствующий локальный файл должен существовать в `public/images/articles/<slug>/`. Внешний URL обложки запрещён. Обложка показывается на странице статьи, в её карточках на главной и в `/articles/`, а также используется как `og:image`. Статья без обложки продолжает собираться в прежнем текстовом виде.

Publisher должен создавать или изменять `.md` и связанные файлы из `public/images/articles/<slug>/` как одну публикационную единицу. Удаление или переименование изображения требует одновременного обновления всех ссылок на него в статье.

## Publication behavior

- builder автоматически обнаруживает все `.md` непосредственно в `content/articles/`;
- все документы, включая черновики, проходят validation;
- published article (`draft: false`) получает HTML-страницу, карточку в `/articles/` и URL в sitemap;
- шесть новейших опубликованных материалов показываются на главной;
- самый новый `featured: true` получает главный акцент; при его отсутствии используется самый новый опубликованный материал;
- `draft: true` не оставляет никаких публичных артефактов;
- порядок определяется по `publishedAt` от новой к старой, а при равенстве — по slug.

## Редакторский workflow

Чтобы добавить статью без изображений, достаточно создать один новый `.md` по контракту. Для статьи с изображениями нужно добавить `.md` и её каталог `public/images/articles/<slug>/` как единый publication package. Чтобы изменить текстовую статью без изменения изображений, достаточно изменить её `.md`. Шаблоны, список материалов, главную и sitemap вручную редактировать не нужно.
